# Eta 上下文压缩改造设计（按 DSH 方案适配）

## 目标

以本地官方 DSH `packages/compaction/compaction-basic/src/` 为完整行为参考，逐项对齐其压缩策略，再按 Eta 已有会话、provider 和摘要架构实现。目标是减少压缩对正常请求的额外耗时与不必要摘要工作，同时保留 Eta 的安全性、兼容性与数据完整性。不是 TypeScript 到 Kotlin 的机械移植，也不是只采纳个别优化点。摘要仍由模型生成。

## DSH 方案行为清单与 Eta 对照

| DSH 行为 | Eta 当前状态 | 适配方向 |
|---|---|---|
| 以实际路由模型的上下文容量和请求压力决策；默认阈值 80%，保留尾部 16%，预留 65,536 tokens | `AgentContextBudget` 已有近似策略与 prompt 用量锚定；Eta 按当前模型配置计算 | 核实每轮路由模型、容量及输出预留是否始终与实际请求一致；补齐缺失的路由级测量/决策，不重复重写已实现部分 |
| 在模型回合边界检查压力 | 已有运行时预算检查路径，待沿调用链验证是否每轮基于最近的真实路由请求测量 | 对照 DSH 的 step-boundary 检查，核实采样时机、数据来源和触发遗漏 |
| provider 确认上下文溢出时绕过普通阈值及保留尾部，强制做一次可行缩减 | Eta 有溢出恢复和有界拆分重试，细节需核对当前实现的绕阈值/尾部语义 | 对齐 DSH overflow 路径，确保不被普通阈值或保留比例阻止，同时仍保留完整工具配对边界 |
| 可选无模型工具结果 pruner；压力触发后先 pruner、重测，再选择摘要区间；溢出时也先 pruner | 当前 Eta 尚未确认有同等独立的裁剪阶段 | 检查本地 DSH pruner 源码和 Eta 工具结果协议，选择语义可证明安全的适配方式；未知结果不裁剪；若不能安全实现则明确记录差异，不能伪称已对齐 |
| 根据按路由计价的 message surface 从尾部累计 retainTokens，选连续旧区间，并向前移动边界以保证工具配对完整 | Eta 目前使用消息数/估算 token 的尾部保护及 `canSplit` 安全边界 | 以 Eta provider 可见请求计价和现有完整批次结构实现对应区间策略；保留 system head、最新用户请求与进行中的工具链 |
| 对阈值未达标的会话不摘要；达标后先做可选 pruner，并重新计量；支持有限次连续 compaction 直至低于阈值 | Eta 有预算、区间摘要和溢出重试，自动多轮压缩行为需核验 | 对齐普通压力与溢出两条路径的先后顺序、重新计量和重试上限；避免重复无收益摘要 |
| 摘要请求重放原对话 system prompt、tools 和消息前缀，把 compaction 指令作为最后 user message | Eta 当前摘要输入使用独立摘要 system prompt 与单独历史内容，和 DSH 有明显差异 | 适配成复用当前路由请求可重放的前缀，尾部追加摘要指令；按 provider 能力处理工具定义和消息格式，关闭摘要期间工具执行；维持 Eta 角色扮演、隐私和摘要验证规则 |
| DSH 可解析不同模型策略、摘要模型及重试等配置 | Eta 配置以模型客户端和现有压缩参数为准 | 先核实 Eta 是否需要新增用户配置；优先复用现有设置。只有架构确有缺口才提出最小兼容配置，不照搬 DSH 插件配置面 |
| 会话压缩采用事务/稳定性校验，提交前确保源区间未变 | Eta 通过候选 JSONArray 验证后整体替换，已有失败保留原文语义 | 保持原子提交与错误回滚；异步摘要期间会话若可变，核验现有版本/稳定性保护是否充分 |

## 关键设计

### 触发与计量

先审计 Eta 从实际 provider 请求、usage 回传到下一模型回合检查的完整路径。压力决策要对应实际路由模型的 context window、该请求输出预留和最近一次真实 prompt token usage；缺少 usage 时才使用 Eta 估算回退。保留现有约 80% 触发、16% 保留、65,536 tokens headroom 的默认意图，但按 DSH 语义核对小窗口与 completion reservation 的预算计算，修正不一致处并加入测试。溢出恢复是独立触发，不受普通压力阈值限制。

### 预裁剪与区域选择

研究 DSH 可选工具 pruner 的源码、被裁剪的结果种类与语义，再检查 Eta 的工具结果表示和持久化形式。只有可证明不会丢失继续任务所需信息的结果才可无模型裁剪；裁剪后重新计量。未知工具、重要状态/证据和工具调用配对保持原样。区域按 provider 可见 token 计价从尾部保留目标预算，再在完整工具交换边界上确定旧区间；当前用户请求和未完成工具链不得丢失。若 Eta 中没有等价安全的 pruner，不进行通用截断，保留该项为明确差异。

### 摘要请求

DSH 的目的不仅是减少待总结内容，还通过重放原请求前缀让新增摘要指令成为尾部差异，以争取 provider prefix/KV cache 复用。Eta 将沿请求适配链确认哪些前缀消息、工具 schema 和 provider 参数能够合法重放；摘要指令位于最后，不调用工具。不同 provider 采用兼容路径，不把对某一协议有效的结构无条件传给其他协议。摘要请求保留 Eta 的敏感信息处理、图片观察降级、角色扮演约束、模型失败校验与失败时原文不变。

### 溢出、重试与事务

溢出时先执行适用的无模型裁剪并重测，跳过普通阈值/尾部策略限制，在完整工具配对边界选取可压缩区间。摘要调用自身若再溢出，按完整组有界拆分；单组过大则失败，不破坏原历史。普通压力触发按 DSH 的有限 compaction retries 逐轮压缩并重测，达到阈值后停止，无收益或超出上限时明确失败。所有变更仍先构造候选结果并验证，之后原子提交。

## 方案选择与取舍

推荐“行为对齐、实现适配”：逐项对齐 DSH 的触发、计量、pruner 阶段、区域选择、摘要重放、溢出和有限重试，使用 Eta 已有数据类型/provider 层实现。相比仅优化当前摘要提示，这能覆盖完整提速链路；相比原样移植，可以避免引入不适用于 Eta 的 Cordis/session event 机制和 provider 假设。无法安全映射的行为以代码证据说明，不做不安全仿制。

## 测试与验收

- 测试实际路由、prompt usage 锚定、context window、completion reservation、80%阈值、近期保留与小窗口预算。
- 测试回合边界触发；未达阈值不摘要；溢出绕过阈值及普通尾部保留约束。
- 测试 pruner（若安全可实现）先于区域选择执行、裁剪后重测、未知/重要结果不裁剪、工具调用结果配对完整。
- 测试区间选取、system head、最新用户请求和未完成工具链保护。
- 测试摘要请求前缀与尾部指令顺序、provider 兼容性、无工具执行、失败保留原会话。
- 测试连续压缩次数上限、溢出分段重试、会话变化校验和原子提交。
- 运行上下文压缩相关单测、全量测试与 Debug APK 构建；报告摘要输入估算、请求次数/重试变化。只有端到端计时可重复时才报告实测提速；缓存命中与其收益由 provider 决定，不能保证。

## 非目标

- 把 DSH 包或 TypeScript 代码直接移植进 Eta。
- 将模型摘要改为纯本地裁剪。
- 无依据地裁剪任意工具输出或牺牲 Eta 的隐私、安全与失败回滚保证。
- 引入 DSH 整套 Cordis、会话日志、手动命令或配置插件系统。
